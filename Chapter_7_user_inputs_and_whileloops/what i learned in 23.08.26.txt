  number % 10 == 0 checks if a number is a multiple of 10 (SEE 7_3)


In Batch 2:

- I started this batch with while loops, learned about a flag (active variable).
  CORRECTION: a flag is NOT the condition by which the loop stops - it is a variable
  (usually True/False) that the while loop CHECKS every time before running again.
  "while active:" means: keep running AS LONG AS active is True.
  When somewhere in the code active is set to False, the loop stops on its NEXT check.
  Note: any value can act as a condition - an empty list/dictionary counts as False,
  a non-empty one counts as True (SEE 7_4)

- Next i also did while loops with numbers and a break statement (SEE 7_5)
  ADDITION: "while True:" creates an infinite loop on purpose - it runs forever
  until a break statement stops it (SEE 7_7)

- I also learned to exit a loop if user types "quit" as input, the if condition will
  pick it up and exit the loop without executing the rest of the code (SEE 7_6)
  ADDITION: there are TWO ways to control a loop from inside:
    * break    -> stops the WHOLE loop immediately, code after it in the loop is skipped
    * continue -> skips only the REST of THIS run (iteration) and jumps back to the top
                  of the while condition, the loop itself keeps going

Summary (corrected):

While loops run AS LONG AS their condition is True. They are best when:
- you don't know in advance how many repetitions you need (e.g. unknown amount of user input)
- you work with lists that shrink/grow (moving items between lists, removing values)
- you need exit conditions controlled from inside (flags, break, quit commands)
A for loop is better when you know exactly WHAT you iterate over (a finished list,
range of numbers, dictionary items).
